EveJS Universal Linux Setup v1.14 — v0.12.8 -> v0.12.9 Upgrade Contract
================================================================================

Supported direct update source: EveJS v0.12.8 only
Target: EveJS v0.12.9 / EVE build 3396210

Transactional sequence
----------------------
1. Require all EveJS/Market/client services stopped.
2. Validate source version and client build contract.
3. Checkpoint and integrity-check authoritative SQLite databases.
4. CRC/path-safety-check and stage a clean v0.12.9 source tree in a sibling directory.
5. Preserve the complete _local tree, full Market data directory, mods, certificates, logs/images and Linux configuration.
6. Three-way merge official configuration defaults while preserving user changes.
7. Install target Node dependencies and smoke-test native better-sqlite3/protobufjs.
8. Do NOT rebuild an existing game store and do NOT reseed Market data.
9. Build the target Market daemon against the staged source.
10. Validate the staged installation, then atomically publish it.
11. Retain the old installation as an upgrade backup and automatically roll back if post-commit validation fails.
12. On first v1.14 launcher start, rotate an older unconstrained CA if needed, publish the v0.12.9 TLS set under _local/certs, reconcile client CA bundles, and apply/verify the exact-hash offline client patches.

The update itself does not mutate authoritative gameplay or Market data. On first v0.12.9 server startup, upstream syncStaticTables.js adds missing tables and refreshes only changed engine-owned static tables; operator/runtime-owned data is retained. Upstream autoInstallContentPacks.js then reconciles the shipped content-pack set.

The copied EVE client remains build 3396210. Its unchanged blue.dll patch is not reapplied. The new LaunchDarkly and crash-upload patches are gated by exact original/upgrade/final hashes and create backups before publication.

Stock-only policy: any installer-managed LU, X-Patch, LU-like or unknown integrated source state blocks the update.
