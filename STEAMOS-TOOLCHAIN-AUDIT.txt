EveJS v0.12.5 Universal Linux Installer v1.5
SteamOS Native Toolchain Failure Audit
=====================================================

Observed tester failure
-----------------------
Cargo failed building:

  libsqlite3-sys v0.28.0

while compiling:

  sqlite3/sqlite3.c

with:

  fatal error: stdio.h: No such file or directory

Source correlation
------------------
The supplied EveJS v0.12.5 release contains:

  tools/market-seed/Cargo.toml

with:

  rusqlite = { version = "0.31", features = ["bundled"] }

The corresponding Cargo.lock resolves:

  libsqlite3-sys 0.28.0

and its build dependencies include `cc`.

Therefore the host must be able to compile bundled SQLite C source. Merely
finding a `cc` executable does not prove that the libc development headers or
native sysroot exist.

Root cause in prior installer
-----------------------------
The previous preflight checked command presence:

  make
  cc
  c++

but did not compile any test program.

A SteamOS image can therefore pass the command-presence test and fail later
during the lengthy market build if development files have been pruned.

v1.5 correction
---------------
- real C compile + execute probe using stdio.h/stdlib.h/string.h;
- real C++ compile + execute probe using iostream/string;
- probes execute before Node/Rust/full installation work;
- SteamOS-specific recovery uses SteamOS development restoration tooling;
- probes repeat after recovery;
- full host toolchain snapshot is preserved in successful installs;
- generic Arch glibc replacement is deliberately not performed on SteamOS.

Protected runtime behavior
--------------------------
The live-accepted v1.4 process-ownership/TLS launcher contract is retained.
