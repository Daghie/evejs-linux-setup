EveJS Universal Linux Setup v1.15 — v0.12.8 -> v0.12.9 Upgrade Contract
================================================================================

Supported direct update source: EveJS v0.12.8 only
Target: EveJS v0.12.9 / EVE build 3396210

Transactional sequence
----------------------
1. Require all EveJS/Market/client services stopped.
2. Validate source version and client build contract.
3. Checkpoint and integrity-check authoritative SQLite databases.
4. CRC/path-safety-check and stage a clean v0.12.9 source tree in a sibling directory.
5. Preserve the complete _local tree, Market data, mods, certificates, logs/images and Linux configuration.
6. Three-way merge official configuration defaults while preserving user changes.
7. Select the platform path:
   - SteamOS x86_64: verify/extract the bundled Node dependencies and static-musl Rust binaries.
   - conventional Linux: preserve the established npm/Cargo source-build path.
8. Smoke-test better-sqlite3/protobufjs and validate the staged Market daemon.
9. Do NOT rebuild an existing game store and do NOT reseed Market data.
10. Validate the staged installation, then atomically publish it.
11. Retain the old installation as an upgrade backup and automatically roll back if post-commit validation fails.
12. On first v1.15 launcher start, rotate an older unconstrained CA if needed, reconcile client CA bundles, and apply/verify the exact-hash network patches for port 443 or SteamOS port 8443.

The copied EVE client remains build 3396210. Its unchanged blue.dll patch is not reapplied. LaunchDarkly and crash-upload changes are gated by exact original/upgrade/final hashes and create backups before publication.

SteamOS safety contract
-----------------------
- No compiler, Cargo, sudo, Pacman, steamos-readonly, sysctl or system package is required.
- SteamOS never falls back to the conventional source-build or privileged-port path.
- The portable archive, exact source lockfiles, important native artifacts and executable modes are verified before use.
- The client and server use localhost:8443, avoiding privileged port 443 without changing SteamOS.

Stock-only policy: any installer-managed Living Universe, X-Patch, LU-like or unknown integrated source state blocks the update.
