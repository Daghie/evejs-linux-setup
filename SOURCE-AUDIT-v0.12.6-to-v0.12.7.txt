6. GAMESTORE / STATIC DATA / CONTENT PACKS
------------------------------------------
tools/DatabaseCreator changed:
  v0.12.6 digest: 2BDBC40F4F573BF757D63579F905926FA867A5A0143553989FDB7A8DB1E841C2
  v0.12.7 digest: F2833CB3139ED6BD6DCED37035930E265BB9B4B47121D0DB2F15576EA7A8D5F4

v0.12.7 adds generated static table dungeonClientContent and changes dungeonAuthority
static data. Therefore generated static game data/manifest are target-version-owned and
must be rebuilt in the update stage.

v0.12.7 adds Content Packs. Source and documentation place the default persistent root at:
  _local/gameStore/content-packs/

The upstream ResetLocalDatabases tool now preserves content-packs by default. v1.10
therefore treats Content Packs as player-owned persistent state and compares exact tree
manifests before/after the static-data refresh.

The authoritative gamestore.sqlite remains preserved through the update transaction.

7. INDUSTRY RUNTIME MIGRATION
-----------------------------
v0.12.7 adds industryInstalledLocationMigration.js. It scans existing industry jobs,
rejects corrupt/ambiguous states, assigns the installed-location field where necessary,
records installedLocationSchemaVersion=1 and durably flushes the migrated state before
the production scheduler proceeds.

This is a first-runtime migration. v1.10 does not execute the EveJS game server during
staging, so it preserves gamestore.sqlite byte-for-byte during the update. The first
successful v0.12.7 runtime may then make the intended migration change.

8. CONFIGURATION CHANGES
------------------------
config/server.json is byte-identical, including the primary service defaults used by the
Linux Launcher.

New official defaults:
  config/mining.json -> industry.industryJobSpeedMultiplier = 1
  config/npc.json    -> targeting.npcPlayerDronesTargetable = true

config/version.json becomes v0.12.7; schema remains 1.

v1.10 uses a three-way merge:
  OLD official default / CURRENT user value / NEW official default

If CURRENT still equals OLD, NEW is adopted. If CURRENT differs from OLD, the user's
value wins. Version-authoritative target metadata comes from v0.12.7.

A fixture using a genuine v0.12.6 config with a user-modified industrySystemCostIndex
confirmed the user value remained intact while both new v0.12.7 defaults were added.

10. LIVING UNIVERSE COMPATIBILITY CONSEQUENCES
----------------------------------------------
The previous loader-based Mod LU package and X-Patch 0.3.2 were audited against
v0.12.6, not v0.12.7.

v1.10 therefore:
  - preserves ordinary loader mods;
  - preserves an existing mods/x-eve-living-universe tree as bytes/state;
  - does not activate that LU loader on v0.12.7 without new compatibility authority;
  - blocks X-Patch 0.3.2 installed/source-overlay state before update staging;
  - never source-merges X-Patch across versions;
  - never offers the old v0.12.6 LU packages as v0.12.7-compatible installs.

12. AUDIT CONCLUSION
--------------------
No large installer/launcher architecture rewrite is required by v0.12.7. A constrained
v1.10 port is justified, but the new DatabaseCreator/static-data work, Content Pack
persistence, industry runtime migration, two configuration defaults and Living Universe
version boundary require explicit updater behavior.
