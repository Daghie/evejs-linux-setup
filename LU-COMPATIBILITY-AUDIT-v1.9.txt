EveJS v0.12.6 Universal Linux Setup v1.9
Living Universe Compatibility Audit
============================================================

User-required boundary
----------------------
Supported runtime states are mutually exclusive:
1. clean/stock EveJS v0.12.6;
2. loader Living Universe at mods/x-eve-living-universe/loader.js;
3. X-Patch Living Universe 0.3.2.

Loader-LU and X-Patch-LU may not be active together.

The v1.9 compatibility logic does not apply, repair, uninstall, or rewrite
EveJS/LU/X-Patch source. X-Patch must be installed/uninstalled by its own patch
manager. v1.9 only detects/verifies an already-applied X-Patch state.

Facts behind the design
-----------------------
The supplied Living Economy root-cause handoff proves an interface-level
source/binary mismatch:
- LU Node code calls GetSeedStocks;
- stock EveJS 0.12.6 Market does not dispatch it;
- X-Patch LU 0.3.2 Rust source does dispatch it;
- the observed live daemon rejected it;
- Health cannot distinguish stock from LU because both report the old
  idempotent-fill-v1 capability;
- the X-Patch package contains Windows native build-freshness orchestration but
  no equivalent host-native Linux shell path.

The handoff specifically recommends source-digest freshness plus no-op RPC
probes for GetSeedStocks and AdjustSeedStocks before Node startup.

Loader Living Universe boundary
-------------------------------
Project evidence shows the user's loader implementation installed under:
  mods/x-eve-living-universe/
with loader.js, sidecar, state and evidence files while clean EveJS audits
remain unchanged.

It therefore retains stock EveJS Rust Market source and uses the stock Market
source profile. v1.9 still computes a read-only digest of the loader-LU tree
while preparing compatibility so the operation can prove it did not modify it.

X-Patch 0.3.2 boundary
----------------------
The supplied X-Patch release was independently verified earlier:
- release 0.3.2;
- manifest EveJS 0.12.6;
- 210 tracked overlay files;
- installed state verification passes on a disposable v0.12.6 tree.

v1.9 requires _local/x-eve-patch/install.json and independently verifies all
210 tracked installed files by path, size and SHA-256. A partial signature
without that authority fails closed.

Market source identities
------------------------
Build-input class mirrors the supplied X-Patch EnsureMarketServer.ps1 freshness
input set: Cargo.toml, Cargo.lock, Rust source, crate Cargo files/build.rs.

Stock EveJS 0.12.6 / loader-LU:
  E9164F59BA3140A4C1AA792D9BF82896D10ED266A43D1BCD062166F77DA9025A

X-Patch LU 0.3.2:
  CA8F89FB0175B9207014E9EEC1461376C195DE0A9F34E7E4490B92C230435A8C

There are eight audited Market build inputs in each current profile. The only
profile differences are the X-Patch market-common/RPC/state source changes
already proven by its installed manifest.

External Market build
---------------------
The helper copies only audited Market Rust build inputs into a temporary source
folder outside EveJS and sets CARGO_TARGET_DIR to an external target folder.
The resulting executable is run through Market doctor while its working
directory remains the original Market directory so existing config/database
paths are authoritative.

The installed source is classified again after compilation. Market source
digest, loader-LU tree digest, X-Patch tracked digest and active mode must all
remain identical. Only then is the external binary accepted and hashed.

Runtime cache:
  <repo-parent>/.evejs-linux-runtime/<repo-path-id>/market-builds/<source-digest>/

Launcher freshness gate
-----------------------
The Launcher does not compile. It requires Installer-prepared external runtime
authority for the currently installed source digest. It verifies:
- current mode/source identity;
- cached Market profile/source digest;
- external executable exists and is executable;
- executable SHA-256;
- started Market PID executes that exact binary;
- HTTP/RPC ports belong to the current Market process tree.

X-Patch-specific startup gate
-----------------------------
The X-Patch profile additionally runs the supplied installed topology-sync
script against runtime market.sqlite/static data, then after Market readiness
performs the handoff-recommended read-only/no-op interface probes:
  GetSeedStocks { keys: [] }
  AdjustSeedStocks { adjustments: [] }
Both must return ok=true before EveJS Node starts.

Market data policy
------------------
Compatibility preparation never seeds, replaces, deletes or resets market.sqlite.
The root-cause handoff explicitly rejects market reseed/database wipe as a repair
for the missing RPC method.

Normal live gameplay can of course mutate runtime persistence. X-Patch's own
provided topology synchronization also writes its runtime Market topology as
part of its documented normal startup contract; it does not rewrite source.

Installer/Launcher separation
-----------------------------
Installer:
- fresh install;
- EveJS version update/rollback;
- runtime compatibility preparation.

Launcher:
- runtime only;
- no Update option;
- no X-Patch install/repair/uninstall;
- no Rust compilation;
- detects/verifies runtime profile, launches exact prepared binary and probes
  X-Patch RPC before Game startup.

Live acceptance still required
------------------------------
The model environment has no native Cargo executable, so this package does not
claim a real Rust compile here. External-copy build orchestration is exercised
with a deterministic fake-Cargo fixture, while a real host-native stock and
X-Patch compile remains a live acceptance gate.
